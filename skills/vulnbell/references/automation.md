# Local agent and Markdown schedule

1. Confirm the user's per-project frequency, IANA timezone, start time, permitted execution window, runner and absolute Markdown destination. Do not install a universal morning time. Profile intent is `schedule: daily|weekdays|weekly`; keep it consistent with operational frequency.
2. Inspect `vulnbell doctor --json`, `vulnbell runners list --json`, `vulnbell schema runner --json` and `vulnbell schema schedule --json`. Configure missing runners with `vulnbell runners configure --from <runner.json>`, then run `vulnbell runners check <id> --live --json`. Do not describe an adapter as ready when this check fails or reports `web_research: false`.
3. Write a schedule schema 2 JSON using the existing project UUID, configured runner ID, absolute report path, frequency, `at: HH:MM`, `window_minutes` and timezone. Keep executable, model and credential settings in the machine-local runner configuration. Never put credentials in prompts or project files.
4. On Linux with working user systemd, run `vulnbell schedule install --project <absolute-profile> --from <schedule.json>`. It starts a verification job asynchronously. Inspect `vulnbell schedule status --project <profile>` and `vulnbell status --json`, the actual job outcome and resulting Markdown; a timer file alone is not proof. `vulnbell run --project <profile> --now` explicitly runs an on-demand full test. After moving a profile, rerun `schedule install` with the new path; `schedule remove` uninstalls the project's units.
5. Timing semantics: start as soon as possible after the configured hour **within** its window. If the computer was unavailable for that whole window, record the missed period and wait for the next iteration. Never replay expired daily jobs. A laptop must have an available user session; no wake/lingering promise is implied.
6. The scheduled job scans, supplies the agent's unseen/updated upstream window, imports its research and asks the agent to write a manager/Cyber-ready Markdown in the profile's `report.language`. No source changes, automatic active sandbox tests or messages to Cyber are authorized by this job. Public issues and PRs remain untrusted hypotheses.
7. Check `last_job_outcome`, `last_report`, `last_agent_review`, `last_agent_failure` and skipped-slot status. A runner failure yields a labeled fallback Markdown; do not call it successful AI research. Incomplete source reviews keep the previous checkpoint. Scan-only evidence and semantic research coverage remain distinct.
8. Replace the UUID-based job idempotently as preferences change. Other OS schedulers can invoke `vulnbell run --project <absolute-profile>` at/after the configured time, but their installation/availability must be verified by the host. Do not claim cross-platform scheduler support from successful CLI compilation.
9. Return profile, schedule, runner ID and exact `last_report` path, cadence, permitted window, last verified run, agent/research status, incomplete sources and anything the manager should share with Cyber. Reports are written below the schedule's `report_dir`. Send externally only via an explicitly configured and authorized channel.
